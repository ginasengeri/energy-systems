PJM Energy Storage System Model

Data quality & validation for the energy storage system (ESS) optimization model

This page summarizes data quality details for the PJM ESS optimization model, queried via the Energy Analytics API (grid=pjm, dataset=ess-model). The model optimizes revenue for a 100 MW / 400 MWh battery from July 1st to September 30th, Q3, and October 1st to December 31st, Q4. This shows earnings both prior to and after the unifying of the RegA and RegD signals in PJM's market.

Key Notes

  1. Q3: The performance, perf, and regulation procured, regd_procured dataset is missing an observation at 03:00 UTC on August 22. This row was excluded to ensure the model receives complete data for every hour.

  2. Q4: The regulation procurement, mileage, and performance dataset contains 4 missing obsevations at 20:00 UTC on October 10, 15 and 23 and 05:00 UTC on December 4. These rows were excluded from Q4's model input data.

  3. The regulation signal is constructed through normalization of the Area Control Error (ACE) for both quarters, due to data accessibility limitations. To construct the RegD signal, a a Butterworth high-pass filter is applied to the ACE before normalization. No filter is applied to Q4s ACE to create a signal slower than RegD but faster than RegA, as described in PJM Regulation Redesign documentation [1].

  4. RMCCP and RMPCP are used to determine regulation prices in accordance with PJM Manual 28 [2].

Dataset Validation

Q3 merged datasets: ess-model, lmp, regd_procured, perf, mileage, rmccp, rmpcp, signal.

There are a total of 2208 hours in Q3. There is one NaN row is in the regd_procured and perf (performance) datasets. This is dropped from the final merged dataset to ensure a complete set for the model to optimize over, resulting in final input set of 2207 hours.

Within reg_metrics, there are three columns: rega_procure, performance and mileage, each with 4 NaN rows in this dataset.
