ENTSO-E Data Pipeline

Technical appendix describing the retrieval and processing of hourly price and cross-border flow data for 2025.

Transmission and market data were collected from the ENTSO-E Transparency Platform API and transformed into time-series datasets containing cross-border physical flows and zonal day-ahead electricity prices. The pipeline retrieves XML responses from the API, parses the structure, reconstructs timestamps, and converts the data into a table for analysis.

Data sources

Two datasets are retrieved from the ENTSO-E API:

  • Cross-border physical electricity flows between bidding zones
  • Day-ahead electricity prices for each zone

The following bidding zones are included in the dataset:

  • France (FR)
  • Germany–Luxembourg (DE-LU)
  • Netherlands (NL)
  • Norway Zone 2 (NO2)

All data are retrieved using authenticated requests to the ENTSO-E Transparency Platform API. 

import requests
import pandas as pd

url = "https://web-api.tp.entsoe.eu/api"

params = {
    "securityToken": API_KEY,
    "documentType": "A11"
}

response = requests.get(url, params=params)

Parsing XML responses

Each response contains Period blocks. Each period specifies a start time and a resolution. Within each period, individual Point elements record a position and a measurement value representing the physical flow or price for that interval. 

import xml.etree.ElementTree as ET

root = ET.fromstring(response.content)

for period in root.findall(".//{*}Period"):
    start = period.find("{*}timeInterval/{*}start").text
    resolution = period.find("{*}resolution").text

    for point in period.findall("{*}Point"):
        position = int(point.find("{*}position").text)
        value = float(point.find("{*}quantity").text)

Reconstructing timestamps

Timestamps are reconstructed from the period start time, the position of each observation, and the resolution of the period. This approach converts the period-based XML structure into explicit timestamps. 

for period in root.findall(".//{*}Period"):

Constructing the flow dataset

Cross-border physical flows are retrieved for multiple directional pairs between bidding zones. For each pair, the API query specifies the exporting and importing domains. 

flows = {
    "FR->DE-LU":  ("10YFR-RTE------C", "10Y1001A1001A82H"),
    "DE-LU->FR":  ("10Y1001A1001A82H", "10YFR-RTE------C"),
    ...
}

Each observation records the flow direction, timestamp, and physical electricity flow value, which are combined into a structured dataset.

With the SDAC 15-minute MTU transition on October 1, 2025, observations switch from hourly to every 15 minutes. Hourly means are calculated following the transition to maintain a consistent interval throughout the dataset.

Constructing the price dataset

Day-ahead prices are retrieved for each bidding zone using a separate API query (documentType = "A44"). In Germany–Luxembourg, the API returns two TimeSeries: sequence 1 contains the main SDAC day-ahead price and sequence 2 contains the EXAA early auction result. For France, a sequence 2 series also appears in the weeks following the SDAC 15-minute MTU transition on 1 October 2025. Only sequence 1 is retained. 

zones = {
    "FR":   "10YFR-RTE------C",
    "DE-LU":"10Y1001A1001A82H",
    "NL":   "10YNL----------L",
    "NO2":  "10YNO-2--------T"
}

Timezone conversion

ENTSO-E timestamps are returned in UTC and converted to German market time (Europe/Berlin). The daylight saving transition on 26 October 2025 causes the local hour between 02:00 and 03:00 to occur twice, producing duplicate rows in both datasets. The duplicate is dropped, keeping the first occurrence.

Validation

Both datasets are inspected before aggregation. The time range, unique zones and directions, and row counts per series are checked. Daily observation counts confirm the switch from 24 to 96 observations per day on 1 October 2025 when the SDAC moved to 15-minute resolution. Any rows with missing prices are removed, as price spreads cannot be calculated with incomplete values. Missing physical flow values are filled with zero — inspection confirmed these correspond to hours where flow in the opposite direction is non-zero, indicating no flow occurred in that direction.

Final dataset

Prices and flows are kept in long format and combined into a single table, where each row represents one hourly observation for one series. A dataset field distinguishes price observations from flow observations, and a series field identifies the bidding zone or flow direction. Calendar fields — month, week, hour, weekday, and others — are added to support filtering and aggregation in Tableau.

Three CSV files are exported: the hourly price table, the hourly flow table, and the combined long-format dataset used for visualization.
